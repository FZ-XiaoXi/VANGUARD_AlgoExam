# Debug_2 调试练习指南：从现象找到代码

这份指南根据你这次练习的过程整理。你适合先运行一个很小的例子，从实际输出找到代码，再把代码拆成几句、代入具体数字理解。先用这种方法练熟；GDB 可以之后再学。

下面包含本次四处错误的复盘，适合修复后回顾。以后遇到新错误，沿用定位过程，不要直接套用这次的修改。

## 1. 先把一条失败看明白

例如：

```text
FAIL | line: 4 | expression: 12 | expected: 12 | actual: 1
```

它表示：测试文件第 4 行，输入 `12`，应该得到 `12`，实际得到 `1`。这里的 `line: 4` 是测试文件行号，不是 C++ 代码行号。

一次只选一条失败，自己算出正确结果，再单独运行：

```bash
cd /home/a/VANGUARD_AlgoExam/Debug_2
make
printf '12\n' | ./build/expression_calculator
```

也可以运行 `./build/expression_calculator` 后手动输入表达式。每次启动只处理一行。

单独运行会显示计算过程。批量测试适合找哪些用例失败，单独运行适合看错误怎么发生。

## 2. 不知道从哪读代码，就搜索输出文字

这是你这次最有效的抓手。

看到：

```text
匹配到 1 个 token.
eval(0, 0) : 1
```

就在编辑器的全局搜索中输入：

```text
匹配到
```

找到打印这句话的代码，向上读到函数开头，才知道负责这一步的函数叫 `make_token`。不用提前猜函数名。

如果要找计算过程，就搜索输出中的固定文字：

```text
"eval("
```

找到打印位置后，查看它所在的函数，再往下读处理过程。行号会随着修改变化，优先搜索文字和函数名。

### 搜到一行声明，还要继续找定义

```cpp
std::int32_t eval(int p, int q);
```

这一行以分号结束，只是提前告诉编译器有这个函数。

继续搜索，找到：

```cpp
std::int32_t eval(int p, int q) {
    // 真正执行的代码在大括号里面
}
```

如果编辑器支持，也可以右键函数名，选择“转到定义”。

## 3. 看不懂一行，就拆开并代入具体数值

不要要求自己一次读懂整个函数。先确认眼前这行的变量代表什么。

| 写法 | 在这里的意思 |
|---|---|
| `e` | 指向输入表达式字符串开头的指针；变量名是作者起的 |
| `position` | 当前读到输入字符串的哪个位置 |
| `substr_len` | 刚匹配到的字符数量 |
| `p`、`q` | 当前计算区间的起始、结束 token 下标，两端都包含 |
| `i` | 循环当前查看的 token 下标 |
| `left`、`right` | 已遇到的左、右括号数量，不代表移动方向 |
| `depth` | 尚未配对的左括号数量 |
| `op` | 选中运算符的 token 下标 |
| `op_type` | 选中的运算符，例如 `'+'` |

常见语法可以先翻译成人话：

```cpp
position += substr_len;  // position = position + substr_len
left++;                  // 左括号计数加一
--depth;                 // 待配对的左括号计数减一
p >= q                   // p 大于或等于 q
A && B                   // A 和 B 都成立
A || B                   // A 或 B 至少一个成立
条件 ? A : B             // 条件成立取 A，否则取 B
```

变量名 `left` 不会让程序向左走；这段循环中真正改变读取位置的是 `i++`。

## 4. 用打印确认猜测

不确定某个变量的值，就在它有效的位置临时打印，例如：

```cpp
std::cerr << "匹配长度: " << substr_len << '\n';
```

想检查数据保存后的内容，就把下面这句放在保存数字的代码之后、`nr_token` 增加之前：

```cpp
std::cerr << "保存后的数字: " << tokens[nr_token].str << '\n';
```

修改后一定先保存，再 `make`，然后重新运行原来的失败用例。

打印语句放在哪里很重要：要看保存后的数据，就放在保存操作之后；要看修改前后的区别，就各打印一次。变量通常只能在定义它的那对大括号范围内使用。

## 5. 四次错误怎样一步步定位

### 输入 12，实际得到 1

先看初次 `eval` 输出的 token。如果已经是 `1`，就优先检查输入保存过程。

搜索“匹配到”找到分词函数，检查处理数字的 `case TK_NUM`。打印匹配长度和保存后的字符串，对照是否一致。

你这次遇到的语句可以分为三个参数：

```cpp
strncpy(复制到哪里, 从哪里开始复制, 复制的长度上限);
```

输入 `12`，匹配长度是 `2`，但旧代码选择的复制数量是 `2-1=1`，因此只保存了 `1`。

正确保存匹配片段的写法是：

```cpp
strncpy(tokens[nr_token].str,
        e + position - substr_len,
        substr_len);
```

输入 `12+3` 时，匹配完 `12` 后 `position=2`、`substr_len=2`，所以 `position-substr_len=0`，找回了 `12` 的起点。这里字符数组事先已经清零，且前面检查了长度，因此复制后仍有字符串结束标记。

可搜索：`C++ strncpy 参数含义`、`C++ 指针加整数`、`C++ 三目运算符`。注意 `strcpy` 和 `strncpy` 是不同函数，先核对拼写。

验证：`1`、`12`、`123`、`120`。

### 8-3-2 应该是 3，实际得到 7

先比较两种计算方式：

```text
(8-3)-2 = 3
8-(3-2) = 7
```

这个规律提示你检查同级运算的顺序。搜索输出中的 `"eval("`，找到计算函数，观察它拆出的左右区间。

如果拆成 `8` 和 `3-2`，再往前追：哪个循环选定了拆分位置？

这段代码规定加减优先级编号为 `1`，乘除为 `2`；`op_level=3` 是比所有有效编号都大的初始值，让首次遇到的运算符能被选中。

选中的运算符要等左右两边算完后才执行。例如选中 `1+2*3` 的加号，右边先算出 `6`，最后才做加法。

对于 `8-3-2`，应选择最右边的减号，把它拆成 `8-3` 和 `2`。循环从左往右扫描，比较条件中的 `<=` 允许遇到同级运算符时更新选择，最终保留最右边的那个。

可搜索：`减法 左结合`、`递归表达式求值 同优先级 主运算符`。

验证：`8-3-2`、`8/4/2`、`1+2*3`、`(1+2)*3`。

### (1)+(3) 被判为括号错误

观察输出：

```text
eval(0, 6) : ( 1 ) + ( 3 )
eval(1, 5) : 1 ) + ( 3
```

程序把不属于同一对的首尾括号去掉了。先找到执行这一步的分支：

```cpp
}else if (check_parentheses(p, q) == true){
    return eval(p + 1, q - 1);
}
```

`eval(p+1, q-1)` 通过缩小区间跳过两端括号，没有删除字符。对于 `(1)`，它正好留下 `1`；改成 `p+2` 会把数字也跳过。

下一步追问：为什么判断函数允许进入这个分支？搜索 `check_parentheses` 的定义，先读它要回答的问题：“整个区间是否被同一对最外层括号包住？”

`return false` 表示不能整体去掉两端括号，不表示整个表达式必然非法。

在纸上跟踪计数：

```text
读到：  (  1  )  +  (  3  )
depth： 1  1  0  0  1  1  0
```

第一个右括号就让计数回到零，但后面还有内容。这说明第一对括号已经闭合，没有包住整个区间。

因此，在处理右括号的循环分支中补充判断：

```cpp
if (depth == 0 && i < q) {
    return false;
}
```

这里的定位过程要分清：看到错误的递归调用，是找到错误现象发生处；继续检查允许这次调用的判断，才找到根因。

可搜索：`括号匹配 计数法`。验证：`(1)`、`(1+3)`、`(1)+(3)`、`((1+3))`。

### 负数结果比正确值大一

先用多个小例子确定规律：`3-2`、`2-2`、`2-3`、`2-4`。将“负数打印不出来”改成更准确的描述：“左边小于右边时，结果比正确值大一”。

在 `eval` 中搜索 `case '-'`，找真正返回计算结果的语句。

文件前面也有 `case '-'`，但那里用 `strcpy` 保存减号，只负责分词。继续找带 `return`、`val1`、`val2` 的位置，才是执行减法的地方。

把 `2` 和 `4` 代入旧代码的三目表达式，就能发现负数分支多加了 `1`。这里应直接返回：

```cpp
case '-': return val1 - val2;
```

可搜索：`C++ 三目运算符 条件成立`。如果怀疑负数类型问题，再查 `C++ 有符号 无符号整数 区别`。正常的 `cout` 可以直接输出负整数。

验证正数、零、负数，以及负数参与后续计算，例如 `(2-4)*3` 应为 `-6`。

## 6. 上网时，把眼前不懂的东西拆成问题

先从代码中提取准确的函数名或语法，再搜索它的意思。例如读不懂整个 `strncpy(...)` 调用，就分别查函数参数、指针加减和三目运算符。

看资料时带着一个小问题：“第三个参数控制什么？”查明后回到代码，代入这次输入对应的数值。必要时复制资料中的简单例子到单独文件验证，不要直接在计算器里大改。

按照考核要求查阅普通网页和文档，不使用生成式 AI、AI 补全或代写服务。

## 7. 每改一处，都回头验证

保存后编译：

```bash
make
```

先测试原失败用例，再测试相邻情况，最后运行完整测试。下面是本次练习的回归用例，使用独立文件保存：

```bash
cat > /tmp/debug2-practice.txt <<'CASES'
1 1
7 1+2*3
9 (1+2)*3
12 12
3 8-3-2
3 (1)+(2)
-1 2-3
4 5/2+5/2
CASES
./build/expression_calculator /tmp/debug2-practice.txt
```

每行第一个数是预期结果，其余内容是表达式。负数允许作为计算结果，输入不支持直接使用一元负号。整数除法向零截断。

这批通过后，可以补充随机测试：

```bash
./build/expression_generator 100 > /tmp/debug2-random.txt
./build/expression_calculator /tmp/debug2-random.txt
```

随机测试不能保证覆盖所有情况。另行手动检查 `1/0`、`1+`、`(1` 等非法输入仍被拒绝；批量文件只能填写预期整数，不能直接表示“预期非法”。修复完成后移除临时打印，保留测试数据和记录。

考试记录可以很短，但要有证据：

```text
输入：
预期结果：
实际结果：
从哪条输出找到代码：
打印或跟踪到了什么：
错误原因：
修改内容：
验证用例与结果：
```

## 8. GDB 是可选的下一步

你这次使用“观察输出 + 阅读代码 + 临时打印”完成了定位，已经是一套调试方法。

GDB 是让程序暂停、查看变量和逐行执行的工具。遇到崩溃、递归输出太多或反复添加打印不方便时，可以再用它。

想体验时，先构建带调试信息的程序。下面的 `make clean` 会清理本目录的 `build`：

```bash
make clean
make CXXFLAGS='-std=c++17 -fwrapv -Wall -Wextra -Wpedantic -g -O0'
printf '8-3-2\n' > /tmp/debug2-input.txt
gdb -q ./build/expression_calculator
```

进入 GDB 后逐行输入：

```gdb
break eval
run < /tmp/debug2-input.txt
print p
print q
print tokens[p]
backtrace
```

`break eval` 表示运行到 `eval` 时暂停；`print` 查看此时的变量；`backtrace` 查看函数调用链。`next` 执行下一行，`step` 可以进入函数，`continue` 继续到下一断点，`quit` 退出。运行后 GDB 会显示当前代码行，先把暂停位置与源码对照，再继续操作。
