# Debug_1 调试指南

这份指南根据本次练习整理。正式考核的错误不一定和练习相同，应根据实际现象排查，不要只背答案。项目说明允许联网查资料，但禁止使用 AI、代码补全和代写服务；以正式考核规则为准。

## 一、先跑起来，确定卡在哪一步

在工作空间根目录执行：

```bash
cd ~/VANGUARD_AlgoExam/Debug_1
source /opt/ros/humble/setup.bash
colcon build
```

构建成功后，在当前终端加载工作空间并启动接收器：

```bash
source install/setup.bash
ros2 run messages_subscriber subscriber_node
```

新开一个终端，加载环境并启动发送器：

```bash
cd ~/VANGUARD_AlgoExam/Debug_1
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 run messages_publisher publisher_node
```

按顺序检查：**能否构建 → 能否找到并启动节点 → 能否读取配置 → 能否通信 → 消息内容是否正确**。修改源码或安装规则后重新运行 `colcon build`，再在运行节点的终端执行 `source install/setup.bash` 并重启节点。停止节点用 `Ctrl+C`。

## 二、本次练习遇到的四处问题

### 1. 构建时报找不到依赖

现象：`colcon build` 报 `CMake Error at CMakeLists.txt:10 (find_package)`，说找不到 `rosidl_default_generator`。

排查时先定位报错中的文件和行号，再将名称与同包 `package.xml` 声明的依赖、本机 ROS 包列表及官方示例对照。练习中名称末尾少了一个 `s`。

```bash
cat src/messages_cpp/package.xml
ros2 pkg list | grep rosidl_default
```

`package.xml` 声明功能包的依赖等信息；`CMakeLists.txt` 包含构建时查找和使用依赖的规则。声明依赖并不保证它已经安装。CMake 包名与 Ubuntu 的 apt 包名也不一定相同，`apt` 搜索不到原名不能直接说明依赖缺失。

**经验：**先读第一条有用的错误，核对名称和环境，再判断是否需要安装；不要因为看到“找不到”就立即安装软件包。

### 2. 节点找不到可执行文件

现象：`ros2 run messages_publisher publisher_node` 输出 `No executable found`。

检查当前终端是否已加载 `install/setup.bash`，然后查看 ROS 找到的可执行文件和实际文件位置：

```bash
ros2 pkg executables messages_publisher
find build install -name publisher_node
```

查看发布器 `CMakeLists.txt` 的 `install(TARGETS ...)` 和 `DESTINATION`，也可以与能正常运行的订阅器对比：

```bash
grep -A 3 'install(TARGETS' src/messages_publisher/CMakeLists.txt
grep -A 3 'install(TARGETS' src/messages_subscriber/CMakeLists.txt
```

本次练习中发布器曾被安装到 `bin`，应安装到 `lib/${PROJECT_NAME}`。修改后需重新构建。注意旧的安装文件可能仍在：**源码规则、已有安装文件和当前运行的程序并不一定同步**。

输入命令时按 Tab 如果显示 `build/`、`src/` 等，通常是 shell 在补全当前目录的文件，不是节点查询结果。用 `ros2 pkg executables` 查询更明确；输入完整命令后按 Enter 才会执行。

### 3. 配置文件安装位置不对

发送器通过功能包共享目录查找 `config/items.yaml`。练习中的安装规则曾多加一层 `resources`，使文件被放到 `resources/config/items.yaml`，与程序查找的位置不一致。

遇到文件找不到时，对照**程序实际查找的路径**和**文件实际安装的路径**：

```bash
find install -name items.yaml
grep -n -A 3 'install(DIRECTORY config' src/messages_publisher/CMakeLists.txt
```

也可查看 `src/messages_publisher/src/publisher_cpp.cpp` 中的 `load_items()`。正常的安装规则把 `config` 目录安装到 `share/${PROJECT_NAME}`。修改后重新构建并重启发送器。

本次无法确定这一处具体何时被改回；旧安装文件也可能掩盖安装规则的问题，所以不应仅凭一次运行成功断定安装规则正确。

### 4. 节点启动了，但没有收到消息

现象：两个节点的话题名分别是 `/item_info` 和 `/items_info`，只差一个 `s`，因此在不同话题上。

两个节点运行时，打开第三个终端，加载 ROS 环境并检查：

```bash
source /opt/ros/humble/setup.bash
ros2 topic list
ros2 topic info /item_info
ros2 topic info /items_info
```

`Publisher count` 是发布者数量，`Subscription count` 是订阅者数量。通信双方需要使用同名话题和兼容的消息类型、QoS；本次先通过话题列表和数量发现名字不同，再检查源码里的 `create_publisher` 与 `create_subscription`。

`/parameter_events` 和 `/rosout` 是常见的 ROS 系统话题，不是本次物品通信的话题。

## 三、如何搜索和核对资料

1. 从报错中提取**工具、版本、关键错误**，例如 `ROS2 humble CMake find_package could not find`。路径和用户名通常不用带上。
2. 项目是自定义消息时加 `custom message`；查节点启动可加 `ros2 run no executable found`；查通信可加 `publisher subscriber not receiving messages`。
3. 优先查对应版本的 ROS 官方文档，再参考社区案例。搜索时可加 `site:docs.ros.org`；想排除 CSDN 可加 `-site:csdn.net`。
4. 在页面按 `Ctrl+F` 搜关键函数或包名，用浏览器翻译辅助阅读。只需先看和当前错误有关的段落。
5. 对照自己的报错、ROS 版本和配置。社区解决方案针对的是别人的环境，不要不加判断地复制命令。

终端中通常用 `Ctrl+Shift+C` 复制选中的文本，用 `Ctrl+Shift+V` 粘贴。

## 四、考试时的节奏

1. 阅读 README，确认目标、允许修改的范围和考试规则。
2. 在正确的工作空间加载环境并构建；记下第一个实质性报错、涉及的包和文件。
3. 一次围绕一个现象排查：读报错 → 查相关文件或状态 → 查资料核对 → 作出小范围修改。
4. 每次修改后重新构建或重启相关节点，确认现象是否消失；不要依靠删除功能、改测试数据或硬编码输出掩盖错误。
5. 构建成功后继续验证节点启动、配置读取和话题通信，最后检查物品是否按 `101 → 202 → 303 → 404 → 505` 循环，`id`、`name`、`info` 与 YAML 一致。
6. 简单记录每处的**现象、定位依据、原因、修改和验证结果**。卡住时保留当前线索，先检查其他可独立验证的部分。

本次最大的改进点是先用命令取得证据，再查对应配置：例如先比较话题数量和名称，再去看订阅代码；比较文件时先确认两边当前内容，避免对着已经修改过的文件寻找不存在的区别。
